# persiana 🚨

**Emergency lockdown** script for Entra ID + Azure. In a serious compromise, it closes the most dangerous entry points that do not depend on internal users, in a single step:

| # | What it does | How | Reversible |
|---|--------------|-----|-----------|
| 1 | Blocks **all external users** (guests/B2B) | Widens the existing CA policy to *all* external tenants and enables it | ✅ restores `state` + `conditions` |
| 2 | Shuts down **SFTP** on every storage account | `isSftpEnabled = false` | ✅ |
| 3 | Disables **enterprise apps** with tenant-wide permissions | `accountEnabled = false` on the service principal | ✅ |
| 4 | Disables **app registrations** that request those permissions | `accountEnabled = false` on their local SP | ✅ |

These count as "tenant-wide" permissions:
- Dangerous application permissions on Graph, Exchange or SharePoint.
- Delegated consent for all users.
- Entra directory roles.
- Azure RBAC Owner, Contributor or UAA on a subscription, a management group or `/`.

The exact list lives in [`persiana.toml`](persiana.toml).

## Safety guarantees

- **Dry-run by default.** Without `--execute`, it only reads.
- **Mandatory preflight.** If permissions or roles are missing, `--execute` refuses to run.
- **Typed confirmation.** You must type `LOCKDOWN <first 8 characters of the tenant ID>`.
- **Allowlist.** It never touches Microsoft first-party apps, the identity running the script, apps listed in `persiana.toml` (Sentinel playbooks, etc.) or the break-glass accounts excluded from the CA policy. If the CA policy has no exclusions, the script will not run.
- **Nothing destructive.** It does not delete secrets, apps or role assignments; it only disables.
- **Rollback with drift detection.** It will not overwrite manual changes made after the lockdown unless you pass `--force`.

## Usage

Requirements: Python ≥ 3.11 (stdlib only) and `az login` with the roles **active** in PIM. See [docs/permissions.md](docs/permissions.md).

Check permissions without changing anything:

```bash
python3 -m persiana preflight
```

Inventory and plan (dry-run, writes `reports/<date>-dry-run/`):

```bash
python3 -m persiana run
```

Lock it down:

```bash
python3 -m persiana run --execute
```

Simulate the rollback from the execution JSON:

```bash
python3 -m persiana rollback reports/<date>-execute/report.json
```

Actually revert:

```bash
python3 -m persiana rollback reports/<date>-execute/report.json --execute
```

Useful options:
- `--only sftp service-principal`: limit to these categories.
- `--only-id <id|appId>`: act only on these objects. Useful for testing against a specific resource.
- `--out <dir>`: change the report directory.
- `--confirm "<phrase>"`: non-interactive confirmation.

Each run produces:
- **`report.json`**: the source of truth. It stores the `before`/`after` state of every object and is the input for rollback. **Keep it safe**: without it there is no automatic rollback.
- **`report.html`**: a self-contained, human-readable report that opens offline and can be attached to the ticket. It shows what was blocked and why, with permissions, owners, credentials, last sign-in and the before/after state.
